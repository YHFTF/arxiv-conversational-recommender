## P0 — 반드시 먼저 수정

- [x] **학습 Negative Sampling 수정** ✅ 2026-09-22
  - 현재 문제: 인용 추천 학습에서 오답을 Paper뿐 아니라 Author/Topic에서도 뽑고 있음.
  - 수정: Negative는 반드시 `Paper`에서만 샘플링.
  - 추가: 실제 positive citation으로 연결된 논문은 negative 후보에서 제외.
  - 목표: 모델이 `관련 논문 vs 관련 없는 논문`을 제대로 구분하도록 학습.
  - 반영: `sample_paper_negatives()`가 0~`num_papers-1` 범위에서만 샘플링하며, train/validation/test/cold 전체의 실제 citation을 제외한다. Author/Topic은 BPR positive와 negative 양쪽에서 제외된다.

- [x] **기존 평가 방식 수정** ✅ 2026-09-22
  - 현재 문제: edge 하나씩 평가해서 `Recall@K`라고 부르고 있음.
  - 수정: Source Paper별로 정답 논문들을 묶어서 Recall@K / NDCG@K 계산.
  - 추가: Train에서 이미 연결된 논문은 Test ranking 후보에서 제외.
  - 목표: 신뢰 가능한 benchmark 확보.
  - 반영: `evaluate_ranking_v2()`는 source paper별 held-out citation 집합으로 Recall@K와 binary NDCG@K를 계산한다. 해당 source의 train citation은 후보에서 masking하며, split 중복 citation은 평가 정답에서도 제외한다.

- [x] **자연어 Semantic Matching threshold 버그 수정** ✅ 2026-09-22
  - 현재 문제: `threshold=0.35`가 있어도 실제로는 유사도가 낮은 단어도 무조건 가장 가까운 D/T/M에 연결됨.
  - 수정: threshold 이하일 경우 `Unknown` 또는 미사용 처리.
  - 추가: Top-1과 Top-2 유사도가 너무 비슷할 경우 불확실한 매칭으로 처리.
  - 목표: 엉뚱한 Domain/Task/Method 강제 매핑 방지.
  - 반영: `run_nl_inference_v2.py`는 최고 유사도가 `--threshold` 미만이거나 Top-1/Top-2 차이가 `--ambiguity-margin`(기본 0.05) 미만이면 `Unknown`/ID 0으로 처리한다.

- [x] **기존 `train_v4_knowledge_bpr.py` 결과 재사용 금지** ✅ 2026-09-22
  - 현재 문제: Best checkpoint를 불러온 뒤 output을 다시 계산하지 않는 평가 오류 존재.
  - 수정: 최종 실험은 `run_benchmark_v2` 기반의 새 benchmark 코드로 통일.
  - 목표: 과거 성능 수치를 그대로 최종 결과로 사용하지 않기.
  - 반영: `run_benchmark_v2`는 기존 checkpoint를 로드해 벤치마크를 건너뛰지 않으며, 이번 실행에서 저장한 best validation checkpoint만 최종 평가에 사용한다. `train_v4_knowledge_bpr.py`도 checkpoint 복원 뒤 output을 다시 계산한다. 최종 성능 보고는 `run_benchmark_v2` 결과만 사용한다.

## P1 — 자연어 추천 방향으로 모델 중심 변경

- [ ] **Synthetic Natural-Language Query 데이터셋 생성**
  - 입력: 각 Paper의 `Title + Abstract`.
  - 보조 입력: Domain / Task / Method.
  - 출력: 논문당 자연스러운 검색 Query 2~3개 생성.
  - 예시:
    - Paper: `Deep Reinforcement Learning for Bipedal Locomotion`
    - Query: `reinforcement learning methods for controlling bipedal robots`
  - 목표: 기존 `Paper → Paper` 학습뿐 아니라 `Query → Paper` 학습 가능하게 만들기.

- [ ] **Query Encoder 추가**
  - 현재 문제: 자연어 질문을 Domain/Task/Method 3개로만 압축해서 세부 정보가 사라짐.
  - 수정:
    - 원본 자연어 Query 전체를 Text Encoder에 입력.
    - Domain/Task/Method는 보조 정보로 사용.
  - 목표:
    - `sample-efficient`
    - `uneven terrain`
    - `recent`
    같은 세부 조건을 보존.

- [ ] **Paper Encoder 구조 변경**
  - Paper 표현을 다음 세 정보를 합쳐 생성:
    - `Title + Abstract` 텍스트 정보
    - Domain / Task / Method 정보
    - Citation / Author / Topic Graph 정보
  - 목표: Text가 중심이 되고 Knowledge와 Graph가 보완하는 구조로 변경.

- [ ] **Query와 Paper를 같은 공간으로 학습**
  - 현재 문제:
    - Paper = Text + 0.1 × Knowledge
    - Query = Domain + Task + Method
    - 서로 다른 방식으로 만든 벡터를 바로 비교하고 있음.
  - 수정:
    - Query와 Paper 각각 Projection/Fusion layer 추가.
    - 최종적으로 같은 차원의 검색용 벡터 생성.
  - 목표: Query ↔ Paper 직접 비교가 가능하도록 구조 정렬.

- [ ] **Query-Paper Contrastive Learning 추가**
  - Positive:
    - Synthetic Query ↔ 해당 Relevant Paper
  - Negative:
    - Query와 관련 없는 Paper
  - 가능하면 Hard Negative 추가:
    - 예: `Bipedal RL` Query의 negative로 `Robot Hand RL` 논문 사용.
  - 목표: 모델이 실제 자연어 검색 문제를 직접 학습.

## P2 — 기존 Knowledge / Graph 자산 재활용 및 개선

- [ ] **Domain / Task / Method를 보조 Feature로 변경**
  - 현재처럼 D/T/M만으로 Query를 만들지 않음.
  - 자연어 Text representation을 보완하는 역할로 사용.
  - 목표: D/T/M 품질이 조금 난잡해도 전체 추천이 무너지지 않도록 변경.

- [ ] **D/T/M Multi-label 지원**
  - 현재 문제: Domain/Task/Method가 여러 개 있어도 첫 번째 값만 사용.
  - 수정: 모든 값을 평균 또는 pooling하여 사용.
  - 예시:
    - Domain = Robotics + Machine Learning
    - Task = Bipedal Locomotion + Control
    - Method = Reinforcement Learning + PPO
  - 목표: 메타데이터 정보 손실 감소.

- [ ] **D/T/M 최소 정규화**
  - 사람이 전체 ontology를 새로 만들지는 않음.
  - 자동으로 정리 가능한 것만 처리:
    - 대소문자
    - 공백
    - 하이픈
    - 명확한 약어
    - 명확한 동의어
  - 예:
    - `RL` → `Reinforcement Learning`
    - `GNN` → `Graph Neural Network`
  - 주의: PPO와 Reinforcement Learning처럼 상하 관계인 개념은 합치지 않음.

- [ ] **LightGCN 역할 변경**
  - 현재 문제: 자연어 추천에서 `get_cold_start_embeddings()`를 사용해 실제 GNN 결과가 거의 빠짐.
  - 수정:
    - Warm Paper: Text + Knowledge + Graph representation
    - Cold Paper: Text + Knowledge representation
  - 목표: 기존 Graph 연구를 유지하면서 자연어 검색을 중심으로 변경.

## P3 — 성능 검증 및 최종 실험

- [ ] **Knowledge Weight Ablation**
  - 테스트 값:
    - 0
    - 0.05
    - 0.1
    - 0.2
    - 0.5
  - 목표: 기존 `knowledge_weight=0.1`에 실험적 근거 확보.

- [ ] **Dot Product vs Cosine Similarity 비교**
  - 현재 문제: Dot Product가 인용 수가 많은 인기 논문에 유리할 가능성 있음.
  - 확인:
    - 논문 인용 수
    - Embedding norm
    - 추천 순위
    사이 관계 분석.
  - 목표: Popularity Bias 완화.

- [ ] **Ablation 모델 비교**
  - Text Only
  - Text + Knowledge
  - Text + Graph
  - Text + Knowledge + Graph (Ours)
  - 목표: 어떤 요소가 실제 추천 성능 향상에 기여하는지 확인.

- [ ] **Human Query 평가셋 구축**
  - 목표 규모: 50~100 Query.
  - 권장:
    - Validation 30
    - Final Test 70 정도.
  - Query마다 후보 Paper의 `Title + Abstract`를 확인하고 relevance 표시:
    - 0 = 관련 없음
    - 1 = 일부 관련
    - 2 = 매우 관련
  - D/T/M은 정답 판정의 기준으로 사용하지 않고 참고만 함.

- [ ] **최종 자연어 추천 평가**
  - 주요 지표:
    - Recall@5
    - Recall@10
    - Recall@20
    - NDCG@5
    - NDCG@10
    - NDCG@20
    - MRR
  - 1차 목표:
    - Recall@10 ≥ 0.40
    - NDCG@10 ≥ 0.35
  - 더 중요한 목표:
    - Text-only baseline 대비 Recall/NDCG 유의미한 개선.

- [ ] **Cold-Start와 Natural Language Retrieval 평가 분리**
  - 실험 A: 자연어 Query를 얼마나 잘 이해하고 관련 Paper를 찾는가?
  - 실험 B: Graph 연결이 없는 신규 Paper도 잘 추천 가능한가?
  - 목표: 서로 다른 문제의 성능을 하나의 숫자로 섞지 않기.

## 최종 목표 구조

`Natural Language Query`
→ Text Encoder  
→ + Domain / Task / Method  
→ Query Vector

`Paper Title + Abstract`
→ Text Encoder  
→ + Domain / Task / Method  
→ + LightGCN Graph Information  
→ Paper Vector

`Query Vector ↔ Paper Vector`
→ Similarity 계산  
→ Top-K 논문 추천

### 개발 원칙

**자연어 추천이 메인이고, Citation Graph와 LLM Knowledge는 자연어 추천을 돕는 보조 정보로 사용한다.**

기존 프로젝트를 폐기하지 않고 다음 자산은 그대로 재사용한다.

- Arxiv 데이터셋
- Title / Abstract
- Citation Graph
- Author / Topic Graph
- Domain / Task / Method
- LLM Knowledge Extraction
- LightGCN 코드
- Cold-Start 아이디어
- 기존 Benchmark 코드 일부
