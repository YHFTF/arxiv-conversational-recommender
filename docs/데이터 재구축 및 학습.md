# 데이터 재구축 및 자연어 추천 학습 계획

## 목적

카테고리 편향을 줄인 OGBN-Arxiv 표본을 다시 만들고, 기존의 인용 기반 그래프 추천 자산을 보조 신호로 활용하면서 자연어 `Query → Paper` 검색 모델을 학습한다.

핵심 원칙은 다음과 같다.

- 자연어 원문 질의와 논문 `Title + Abstract`가 검색의 중심이다.
- Domain / Task / Method(D/T/M)는 필터링, 재정렬, 설명을 위한 보조 메타데이터다.
- 새 표본을 만들면 노드 구성과 로컬 인덱스가 바뀌므로, 인덱스에 종속된 기존 산출물과 모델 가중치는 재사용하지 않는다.

## 기존 데이터 처리 기준

| 구분 | 파일 또는 데이터 | 처리 | 이유 |
| --- | --- | --- | --- |

| 균형 표본 | `subdataset/ogbn_arxiv_16k_ffs_sample.pt` | 재생성 | 새 카테고리 균형 Forest Fire 표본으로 교체한다. |
| 논문 마스터 | `subdataset/arxiv_master_final.json` | 재생성 | 새 논문 집합과 새 로컬 인덱스에 맞춰야 한다. |
| OpenAlex 저자 정보 | `output/author_data_openalex.json` | 재생성 | 새 표본 논문에 대해서만 다시 수집한다. |
| 논문 인용 에지 | `subdataset/paper_paper_edges.pt` | 재생성 | 새 표본 내부 인용 관계만 남겨야 한다. |
| 저자-논문 에지 | `subdataset/author_paper_edges.pt` | 재생성 | 논문 로컬 인덱스가 바뀐다. |
| 이종 그래프 | `subdataset/build_hetero_graph.pt`, `subdataset/build_hetero_graph_v2.pt` | 재생성 | 노드, 에지, 피처의 정렬 기준이 모두 바뀐다. |

| D/T/M 용어 임베딩 | `output/knowledge_meta_embeddings.pt` | 재생성 | 메타 사전의 항목 및 ID 순서가 달라질 수 있다. |
| 기존 모델 가중치 | `output/lightgcn_*.pt`, `output/benchmark/*.pt` | 폐기 또는 별도 보관 | 이전 그래프 및 노드 인덱스에서만 유효하다. |
| 과거 벤치마크 결과 | `output/benchmark/*.json` | 보관만, 성능 비교에 미사용 | 이전 표본 분포에서 나온 결과다. |

> 삭제가 필요하면 즉시 삭제하기보다 `archive/<날짜>/`로 옮긴 뒤 새 파이프라인의 정합성 검증이 끝난 후 정리한다.

## D/T/M 데이터 재구축 원칙

D/T/M은 버리지 않는다. 다만 자연어 질의를 Domain 1개, Task 1개, Method 1개로 압축해 검색 벡터를 만드는 현재 방식은 세부 제약을 잃으므로 새 검색 모델의 주 입력으로 사용하지 않는다.

각 논문에는 다음을 저장한다.

```json
{
  "paper_id": "...",
  "node_idx": 0,
  "title": "...",
  "abstract": "...",
  "arxiv_categories": ["cs.RO", "cs.AI"],
  "authors": [],
  "knowledge": {
    "domain": ["Robotics", "Machine Learning"],
    "task": ["Bipedal Locomotion", "Control"],
    "method": ["Reinforcement Learning", "Proximal Policy Optimization"],
    "normalized": {
      "domain": ["Robotics", "Machine Learning"],
      "task": ["Bipedal Locomotion", "Control"],
      "method": ["Reinforcement Learning", "Proximal Policy Optimization"]
    },
    "confidence": 0.91,
    "evidence": ["문장 또는 초록 내 근거"]
  }
}
```

- 원문 추출값과 정규화값을 모두 보존한다.
- 각 필드는 다중 레이블을 허용한다.
- 대소문자·공백·명확한 약어와 동의어만 최소 정규화한다.
- 불확실한 값은 억지로 사전에 매핑하지 않고 `Unknown` 또는 빈 값으로 둔다.
- ArXiv 공식 카테고리는 LLM 추출값과 별도의 안정적인 분야 신호로 보존한다.

현재 파일명도 정리해야 한다. `code/data_collection/arxiv_master.py`는 `output/3llm_extraction_results.json`을 읽지만, `code/data_analysis/llm_keyword_extraction.py`는 `output/llm_extraction_results.json`을 쓴다. 재구축 전 두 경로를 하나로 통일해야 새 D/T/M이 마스터 데이터에 반영된다.

## 자연어 추천을 위해 새로 필요한 데이터

| 신규 데이터 | 권장 내용 | 사용 목적 |
| --- | --- | --- |
| 정규 논문 레코드 | `paper_id`, `node_idx`, 제목, 초록, 공식 카테고리, 저자, 날짜, D/T/M | 모든 파생 데이터의 단일 기준 데이터셋 |
| 논문 텍스트 임베딩 | `Title + Abstract` 임베딩, 인코더 모델명·차원·버전, `paper_id` 매핑 | Paper encoder 입력 및 빠른 후보 검색 |
| Query–Paper 학습쌍 | 논문당 자연어 Query 2~3개, positive `paper_id`, 생성 출처와 품질 플래그 | 자연어 검색 학습의 정답 데이터 |
| Hard negative | 같은 분야이지만 다른 Task/Method 논문, 또는 텍스트상 근접하지만 비관련인 논문 | 유사해 보이는 오답을 구분하도록 학습 |
| AI 판정 평가셋 | Query, 고정 후보 논문 풀, AI relevance 0/1/2, train/validation/test 분리 | 수동 라벨링 없이 자연어 검색을 상대 비교 |
| 재현성 메타 | 표본 seed, 카테고리 분포, 프롬프트·LLM·임베딩 모델 버전 | 실험 재현과 데이터 버전 추적 |

### Query–Paper 학습쌍 예시

```json
{
  "query_id": "synthetic-000001",
  "query": "reinforcement learning methods for controlling bipedal robots on uneven terrain",
  "positive_paper_ids": ["123456"],
  "source": "synthetic",
  "quality": "reviewed",
  "hard_negative_paper_ids": ["234567", "345678"]
}
```

인용 에지는 그래프 보조 학습과 cold-start 평가에 활용할 수 있지만, 자연어 검색의 정답 데이터로만 간주해서는 안 된다.

### AI 생성 질의·평가셋

수동 검수가 불가능한 경우 `code/data_analysis/build_nl_recommendation_data.py`가 다음을 생성한다.

- `paper_text_embeddings.pt`: `Title + Abstract + D/T/M`의 검색용 논문 임베딩
- `queries.json`: 논문별로 생성한 연구자 스타일 질의와 anchor 논문 ID
- `judgments.json`: 질의별 고정 후보 풀과 AI relevance(0/1/2) 판정
- `manifest.json`: 입력 논문 순서의 해시와 재현성 메타데이터

질의는 제목·저자·논문 ID를 쓰지 못하게 제한한다. 후보 풀은 anchor 논문, 인용 이웃, 동일 D/T/M 논문, 무작위 논문을 섞어 만들며, relevance 판정 모델에는 후보의 제목·초록·D/T/M만 제공한다. query의 anchor 논문 단위로 train/validation/test를 80/10/10으로 고정 분할한다.

```bash
# API 호출 없이 재구축 데이터의 정합성만 확인
venv/bin/python code/data_analysis/build_nl_recommendation_data.py --prepare-only

# 권장: 임베딩, 300개 anchor의 질의 2개씩, 후보 판정을 단계별 생성/재개
venv/bin/python code/data_analysis/build_nl_recommendation_data.py --stage embeddings
venv/bin/python code/data_analysis/build_nl_recommendation_data.py --stage queries --query-count 300 --queries-per-paper 2 --concurrency 20
venv/bin/python code/data_analysis/build_nl_recommendation_data.py --stage judgments --candidate-count 32 --concurrency 10
```

동일 모델이 질의와 판정을 모두 수행하면 모델 편향이 평가에 들어갈 수 있다. 최종 보고용 세트는 `--judge-model`에 질의 생성 모델과 다른 모델을 지정해 교차 판정하거나, 소규모라도 표본 감사를 권장한다. AI 판정값은 절대적 사용자 선호 점수가 아니라 모델 간 상대 비교용 weak label로 해석한다.

## 권장 모델 구성

```text
원문 Query ───────> Text Encoder ───────────────────┐
D/T/M ────────────> Metadata Encoder / Filter ──────┼─> Query–Paper 검색
Title + Abstract ─> Text Encoder ───────────────────┤
Paper D/T/M + Citation / Author Graph ──────────────┘
```

- Query와 논문 원문 텍스트를 동일한 검색 공간으로 학습한다.
- D/T/M은 텍스트 표현에 더하는 보조 피처, 필터, 재정렬, 추천 근거로 쓴다.
- Warm 논문은 Text + D/T/M + Graph, cold 논문은 Text + D/T/M 표현을 사용한다.
- 기존 인용 BPR 모델 가중치는 새 Query–Paper 모델의 초기 가중치로 직접 재사용하지 않는다.

## 재구축 및 학습 순서

1. `forest_fire.py`로 고정 seed의 카테고리 균형 표본을 생성한다.
2. 새 표본에 대해 논문 ID, Title/Abstract, OpenAlex 저자 정보를 매핑한다.
3. 표본 내부 인용 에지와 저자-논문 에지를 다시 생성한다.
4. D/T/M을 다중 레이블, 정규화값, 신뢰도, 근거와 함께 다시 추출한다.
5. `arxiv_master_final.json`, D/T/M 사전, 이종 그래프를 새로 생성한다.
6. `Title + Abstract` 기반 논문 텍스트 임베딩을 생성한다.
7. 논문별 synthetic query 2~3개와 hard negative를 생성하고, 일부는 사람이 검수한다.
8. 사람 검증 Query를 논문 단위로 분리한 validation/test 세트로 구축한다.
9. 아래 순서로 모델을 비교한다.
   - Text only
   - Text + D/T/M
   - Text + Graph
   - Text + D/T/M + Graph
10. 최종 평가는 자연어 검색과 인용 기반 cold-start 평가를 분리해 보고한다.

## 완료 확인 항목

- 모든 파생 파일의 `paper_id`와 `node_idx`가 새 표본과 일치한다.
- 새 표본의 카테고리 분포와 seed가 기록되어 있다.
- 이종 그래프의 Paper 노드 수와 마스터 레코드 수가 같다.
- D/T/M 사전과 메타 임베딩의 ID 순서가 같다.
- Query–Paper 학습·검증·테스트는 논문 기준으로 겹치지 않는다.
- 이전 모델 가중치와 벤치마크 결과가 새 실험 결과에 섞이지 않는다.
